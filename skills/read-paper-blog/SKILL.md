# 论文与英文博客阅读

默认交付完整中文技术笔记，保留关键英文术语，重点解释问题、设计动机、工作机制和工程意义。假定读者有机器学习基础；对本文特有的概念和理解方法必需的背景做解释，不从通用基础知识开始长篇铺垫。用户指定阅读重点、输出位置或只需对话解答时，以当前要求为准；只需对话解答时不创建笔记或持久归档文件。

用户要求离线或仅基于提供内容时，该限制适用于论文、博客和补充资料：不联网获取原文、确认最新版本或核验当前软件行为；按已有材料解读，并明确哪些信息未核实。

## 获取和确认原文

- 接受 arXiv 链接或编号、论文 PDF 链接、本地 PDF、英文博客链接及用户提供的正文。用户只给出标题时，先查根 `README.md` 的题目列与 `papers/` 归档——命中唯一就直接复用该行的编号与归档（不重复归档、不新建编号），命中多行或含糊时先确认文章身份。
- 对在线来源实际获取原文，不能用搜索摘要代替全文。优先使用环境已有的网页、PDF 和文件读取能力，不假定某个专用工具存在，也不默认安装依赖。
- **博客正文抓不到时先去源码仓库**：JS 构建的单页应用（Vite/Next 等）在 HTML 里只留一个 `#root` 壳与打包产物，正文是内嵌在 JS bundle 里的 markdown 字符串。到站点源码仓库取源文件（如 `site/src/data/blog/*.md`），**把 commit 与文件 sha256 记为版本锚点**；`raw.githubusercontent.com` 不可达时用 GitHub API 的 blob 接口兜底（`/repos/<owner>/<repo>/git/blobs/<sha>` 返回 base64）。双语站点两个语言版本都取回交叉核对——常见只更新一侧。
- 对 arXiv 链接或编号，指定版本时使用该版本；未指定时先从官方元信息确认最新版本，再获取该版本。若只能获取较旧版本，明确说明，不称其为最新版。正文、PDF、图表和补充材料应来自同一版本，不能混用不同版本的实验数字。
- **同一工作常有多个发布渠道**（项目页/预印本、arXiv、OpenReview、期刊）。**材料自述的状态不是核验结果**：仓库 README、项目页、CITATION 里写的发布渠道、许可、版本、star 都要独立核验并注明核验方式与日期（实际发生过：仓库 README 写 "arXiv posting 🔜 / in progress"，而 arXiv 上该文早已有 v1、其后又更新到 v2）。发现其他渠道的版本后，**用多组关键句检索**比对关键数字与关键表述，不能只看标题与摘要就断定是同一版本；各版页数也要分别记录（同一工作可能是 36 页与 43 页两个不同版本）。
- 记录标题、作者或机构、来源链接、发布日期和阅读日期；arXiv 论文额外记录编号和版本，已保存的 PDF 记录本地路径。不适用的字段省略，适用但无法确认的字段注明未知，不猜测。用户提供的本地文件或正文无法确定线上身份时，以提供内容为准。
- 本地 PDF 可能是删减笔记或注释版。先判断其性质，不把仓库现有的学习笔记当成论文完整原文。允许联网且能确认来源时，可补充获取对应版本的原文，并说明两者关系，不能用最新版悄悄替换用户提供的版本。
- 论文可使用同版本 HTML 或 LaTeX 辅助理解；arXiv 论文获取全文仅用于阅读与核对，不归档 PDF；非 arXiv 来源的论文默认归档时尽力获取对应的原文 PDF。不能因 PDF 不可得而放弃对已有正文的解读。核对文本抽取容易损坏的公式、上下标和表格：表格数字与公式以 PDF 版式文本或渲染页为准（HTML 线性化表格易丢列错位），不凭文本抽取直接下结论。把多列表格转写进笔记（重排、摘列或改列名）后必须回渲染页**逐格复核**，不能按位置对照——宽表转写是列错位高发点（实际发生过摘要表两列数值整体写反）；列多的表优先照抄原文列序，再另行注释。
- 图中的定量读数（曲线起止/平台值、柱高、倍数）不靠缩略图目读：先放大核对坐标轴量程与刻度标签文字本身，再读数；支撑结论的关键读数（如「从 X 升到 Y」）用像素测量复核（方法见 check-paper-note 的「读图的像素测量」），并在笔记中标注「图中读数」与近似程度，与论文数字区分。低分辨率下误认刻度是此类错误的主要来源（实际发生过把 7–14 的纵轴读成 3–15、把坐标轴下限当成曲线起点）。
- 获取失败时尝试可用的官方页面或另一种原文格式；仍失败则说明缺失范围。只有摘要时只能输出标明“仅基于摘要”的有限解读；需要全文才能回答的问题暂不下结论。不能把 HTML 错误页保存为 PDF，也不能声称已归档未获取的原文。

## 阅读与分析

先梳理文章整体结构，再阅读正文及理解核心方法、训练目标或实验结论所需的附录。长文按章节或页码分段读取，检查工具输出是否截断；保留关键证据的位置，不能把一次读取成功等同于已获取全文。结合关键图表建立论证链条，不能只读摘要和结论就交付完整技术解读。实际未读到的部分要披露。

### 论文笔记

按内容组织以下信息，允许合并章节，避免没有内容的固定模板：

1. **核心结论**：文章解决什么问题、核心方法是什么、结果说明什么，以及适合什么场景。
2. **问题与动机**：已有方法的具体瓶颈，本文依赖的前提及必要背景。
3. **方法与贡献**：说明输入、输出、核心组件、数据流和训练或推理过程；将作者声称的贡献与原文实际提供的证据分开。显式覆盖两类易漏内容：① 相对前代/同类工作的**结构性变化**（架构替换、模块增删、简化——常写在引言与架构图里）；② 论文自报的**关键效率数字**（FLOPs / 每 token 字节 / token 预算 / 吞吐——常出现在引言与独立效率图）。
4. **关键公式与直觉**：解释必要的变量、维度、假设、目标函数和关键推导。沿用原文符号，**上下标与向量/矩阵记号逐条从渲染页抄写**（文本抽取会丢失或混淆上下标，必要时裁剪放大核对），交付前对每条公式做一次「渲染页 ↔ 笔记」对照。区分原文推导与为教学补充的推导。不要为覆盖所有公式而机械转抄。
5. **实验与证据**：分析关键图表、数据集、基线、指标、消融和实验条件。记录有解释价值的数值，说明比较是否控制模型规模、数据、算力或推理预算。区分相对提升、百分点变化及不同指标方向，不将特定条件下的收益泛化为普遍结论。写下「全部/均/全面/无一例外」类全称断言前，回表格逐项找反例（实际发生过「性能全面超过前代」与表格中三处更低的值冲突）；有反例就改用具体范围表述。**原文自述与自己表格/附录对不上的地方也要记录**（摘要口径与表值不符、正文宣称的覆盖范围有反例、称某组数字「在 Table n」而该表没有这几行）——笔记正文改用可复算的表值并注明出处，把差异单列成「原文自身的表述张力」一节，别把它当成本文结论。
6. **工程视角**：解释实现步骤、关键接口或张量流、计算和存储成本、依赖条件及可能的失败模式。必要时给最小例子或伪代码；只有原文或推导支持时才量化成本，不将示意代码说成作者实现。
7. **局限与待确认问题**：区分作者明确讨论的局限和读者根据证据提出的判断，指出哪些问题尚无实验证据。

默认不运行文章附带的代码、不训练模型、不开展复现。下载、文本提取、PDF 渲染和文件校验等阅读辅助操作可正常使用。用户明确要求复现时，再按其范围处理。

### 博客笔记

围绕核心观点、论证过程、技术机制、关键代码或案例、实践建议及适用边界展开。技术教程要讲清操作的前提和关键步骤；观点文章要区分经验判断、可验证事实与推测。不强行加入论文式实验、贡献或消融章节。

**导读、综述、awesome list 这类转引型材料**（自己不给数据，只转述 N 篇论文）：笔记里按条目标注每条数字的核对层级（元信息／摘要／全文／复算／未核），并单列材料自身的省略之处（未引的更强结果、被省略的限定词，如子集口径）；材料没说的内容标成「补充背景」并注明取自哪篇论文。逐篇核到什么程度以及核对的目标（转引忠实 ≠ 结论成立），见 check-paper-note 的「转引型材料的核对」。

代码示例应解释关键行为、依赖及上下文。文章中的历史版本和当下行为需要区分；用户需要当前可用方案且允许联网时，查询对应官方文档并标注补充来源。无法核验时，只说明文章所述版本的行为，不宣称当前仍然适用。

## 证据与表达

- 以中文解释为主，首次出现的重要术语附英文，公式使用 Markdown 数学表达。优先用具体例子解释抽象机制；流程确有帮助时可画 Mermaid 图。
- 关键结论和数据就近注明章节、公式编号、图表编号或原文小节链接。PDF 页码有歧义时注明是文件页码还是正文页码。**自己按表格复算或推算出来的数字**（百分点差、相对提升、平均值）标注为「本笔记复算」并与论文原数字区分；**复算要写明口径**——均值 / 单项原始变化 / 相对变化 / 百分点，不能混写（实际发生过把「六数据集均值改善 656 ms」与「单个数据集的原始变化 −4934 ms」并成一句）。无法找到定位信息时不要编造；无法核实的实现细节（如代码仓库某个目录的作用）要么查清再写、要么略去，**不在正文留「？」式猜测**。
- 写「摘要 / §x / 图注 / 正文 说…」这类**归属句**之前，回渲染页确认该句所在的**页与小节**：跨页论文的摘要、引言与结论常用近似措辞（实际发生过把 §1 引言里的一整段逐域结果声明写成「摘要写」，而摘要全篇没有数字），凭通读印象归属会写错。
- 明确标记“作者结论”“补充背景”“解读/推断”等证据层次，尤其不要把工程建议或自拟伪代码归于作者。
- 仅在理解原文所需时补充查阅外部资料，优先论文、官方文档或作者材料，单独注明来源；不自动扩展为大范围文献综述。
- 博客以自己的表述总结，少量必要引用附来源，不默认复制或翻译归档整篇第三方文章。

## 保存笔记和原文

本 skill 所在目录为 `<仓库根目录>/skills/read-paper-blog/`，默认以该仓库根目录定位 `notes` 与 `papers`，不依赖调用时的工作目录；若通过符号链接加载，先解析其真实路径再定位仓库根目录。只有实际阅读时才创建产物目录。

| 来源 | 默认产物 |
| --- | --- |
| arXiv 链接或编号 | 笔记 `notes/papers/<arxiv-id>-<version>-<短标题>/note.md`（不归档 PDF，note 中记录官方 arXiv 链接） |
| 其他来源的论文 | 笔记 `notes/papers/<短标题>/note.md`，原文归档 `papers/<编号>-<短标题>.pdf` |
| 英文博客 | `notes/blogs/<站点>-<短标题>/note.md` |

arXiv 论文仍会获取完整原文用于阅读和核对，只是不把 PDF 归档进仓库。

归档编号为 5 位零填充，接续现有编号递增（编号数与条目数不必相等，不保证连续）。同一个条目沿用原编号，不复用、不跳号、不改号；**分配前现查**`papers/` 文件名、根 README 编号列与上游归档仓库三者的最大值，不凭记忆也不写死（只看一侧会在归档文件缺失时发出重复编号；上游不收录非论文条目，序列会与本仓库错位）。

- **论文与非论文条目共用一条编号序列**：导读、博客、系统这类条目按用户要求收录时同样占号。它们没有可归档的 PDF，该行编号单元格直接指向原文在线地址，不写 `papers/` 路径；分组按其署名方，归并规则见「回写根 README」一节（只有 1 个条目的单位不新建分组，并入「### 其他」）。
- 从上游导入论文时若编号已被本仓库的非论文条目占用，顺延取下一个空号，不覆盖已占用条目。
- 目录使用简短、稳定的英文 slug。将编号或标题中不适合路径的字符替换为连字符；例如旧式 arXiv 编号中的 `/`。版本使用 `v1`、`v2` 等，无法确认时注明 `version-unknown`，不编造版本号。
- 写入前检查现有目录和笔记中的来源信息。比较 arXiv 身份时使用编号和版本，不以 abs、pdf 或 html 链接形式判断是否同一篇。同一论文已有笔记目录时优先复用，不因来源或短标题变化而重复归档（例如清单里记的是 GitHub 版、本次给的是 arXiv 链接）；只有已有笔记记录的是另一个 arXiv 版本（已有 v1、本次读 v3）时才按版本另建。非 arXiv 来源论文若发现同时存在 arXiv 版本：仍按本次阅读来源与既有归档处理（不改目录名、不换归档策略），但在来源信息中记录 **arXiv 编号 + 核验状态（核验方式与日期；不可达就写「未核验」）+ 版本关系**——不要只写「疑似编号」。**若基准版不是最新公开版**：不换基准、不改归档，但要给出「版本关系」小节（各版页数与日期、关键数字是否一致、正文与图/表编号是否变动、新版有哪些内容本笔记未覆盖），并给笔记里对具体版本的论断（尤其「原文自身的表述张力」）标注适用版本。
- 不同来源发生名称冲突时追加 arXiv 编号或来源 URL 的短哈希。无 URL 的本地材料使用文件内容的 SHA-256 前 12 位；提供的正文使用文本内容的同类哈希。版本未知或非 arXiv 来源论文的文件发生变化时，先比较内容，无法确认是同一版本则使用带内容哈希的新目录，不覆盖旧文件或混合解读。博客同一 URL 内容更新时复用目录，并为新解读标注阅读日期。
- `note.md` 开头列出来源信息、阅读范围和原文链接；arXiv 论文记录官方 arXiv 链接；非 arXiv 来源的论文使用 `[原文 PDF](../../../papers/<编号>-<短标题>.pdf)` 关联已归档的文件，并记录页数与 sha256（便于下次复核对齐版本）。阅读范围分两级写：「已渲染并逐项核对（含像素测量等）」与「仅按正文/图注引用」，且声明里提到的核对手段必须在笔记中有对应产出（声明了像素测量就要有图中读数）；**同时记下可复现的核对凭据**——渲染 DPI、裁剪框像素坐标、定标锚点（如「网格线 y=1072 ↔ 2.0」）、否定性断言的检索词，下次复核可直接复用，也让「声明了却没做」一眼可查。**声明只能写已经做完的事**：表格与公式的渲染页核对要在写完笔记之前完成，不能先把「已逐格核对」写进声明再去补做（实际发生过声明里列了 5 张表和 3 个公式、当时只读了 HTML 版）。获取 PDF 失败时注明未归档，不生成失效的本地链接。
- 博客没有版本号，来源信息要记**能锁住版本的东西**：标题（各语言版本的题名都记）、站点与署名方、源文件路径 + commit + sha256、发布日期、原文在线地址、许可状态（站点/仓库未标注时如实写「许可未标注」，不默认套用）、配图来源与许可；条目已占编号时另记仓库编号。转引型材料还要写明对被引论文核到哪一层。
- 在线 PDF 先下载到临时文件，检查文件标识并用可用的 PDF 读取工具确认可读，核对标题及可确认的版本；非 arXiv 来源的论文核对后归档为 `papers/<编号>-<短标题>.pdf`，arXiv 论文仅用于本次阅读与核对、用后清理临时文件、不保存。下载或验证失败时清理本次临时文件，保留已有有效文件。只有文件扩展名或 HTTP 成功状态不足以证明它是正确的 PDF。多 MB 的 PDF 可能超过单次命令超时：改用后台下载或分段重试，校验必须等文件完整（`pdfinfo` 能解析、页数合理）；半截文件的 xref/trailer 报错是下载未完成的预期现象。内置网页抓取被网络策略拦截时改用 curl 等命令行工具；域名完全不可达（本机实测 huggingface.co）时如实记录「链接无法验证」，不冒充已验证。
- 非 arXiv 来源论文的本地原文原样复制为 `papers/<编号>-<短标题>.pdf`；注释版、删减版或性质无法确认的用户 PDF 原样保存为该篇笔记目录下的 `provided.pdf`，在笔记中以“用户提供的 PDF”链接，不称为原文。能获取对应原文时另外归档到 `papers/`（arXiv 论文不保存）。已有相同文件不重复保存或覆盖；同一论文版本下存在内容不同的用户 PDF 时，使用 `provided-<内容短哈希>.pdf` 分别保留。无法确认版本时如实记录。
- 明确记录本次解读实际基于哪些材料。补充归档完整 PDF 不代表已阅读它；先前仅基于摘要或删减版的笔记不能因补存原文就自动标为完整解读。
- 重复阅读时先读已有笔记，保留人工内容、批注和待办；将新解读补充到合适位置，不能区分内容归属时追加带日期的补充，不整篇覆盖。
- 需要引用本地图表图片时，按需放入该篇目录下的 `assets/`，使用相对链接，注明图号和来源；仅使用有助于解释的图表。**独立图片文件（博客/项目站的 PNG、SVG）整图复制、不裁剪**——一步规避越界、黑边与像素差三类风险；**论文的图嵌在 PDF 页里，只能从渲染页裁**：**裁剪前先在整页渲染上做行/列剖面，标出该图的完整内容范围**——含图内标题、图例、坐标轴标签、Zoom-in 子框等离图形主体较远的元素（图的第一个内容行可能紧接页眉之下，与主体相隔十几个空白行）。**不要只凭视觉框选**：按「图框」裁会把图内标题整块丢掉（实际发生过首版裁掉图内顶部的 "Update Policy" 标注，而边缘干净、像素差比对也通过——缺的不是边缘而是整块元素）。边界取在内容范围之外、图注之间的空白行，别把图注切一半（下边界位置可用像素行扫描找题注首行的 y 坐标来确定），并保留图例、坐标轴与刻度完整，分辨率足够（约 ≥200 dpi）。注明来源与许可——arXiv 版默认多是 `nonexclusive-distrib` 而**不是** CC，按 abs 页「view license」指向的实际协议写；非 arXiv 来源未见许可标注时如实写「许可未标注」，不默认套用。裁剪框先校验在图像尺寸内（越界会被工具静默补黑边——实际发生过成品图约 35% 是黑边、内容截断而未发现），**每次改动裁剪框后都要重新回看成品图**，并分两步核验：① 边缘像素干净（无黑边/越界/截断/切字）；② **对照上面标出的内容范围，确认没有缺元素**——只做①会把「整块元素被排除在外」漏掉。再与原文同区域重裁做像素差比对（差异应≈0）；像素差只证明「与原文同位置一致」，不证明「这块位置选得对」，两者要分别确认。
- 在来源信息里下**整类声明**（「插图均为示意图」「未做像素测量」「未从图中读数」）之前，先把手头全部图过一遍：论文与导读里常混着带色标、内嵌柱状/折线图的定量图（实际发生过声明「均为示意图」而其中 2 张含定量元素，复核时被抓出）。声明只覆盖真看过的范围，没看的写「未逐张检查」。
- 博客默认保存笔记及原文链接，不归档整篇正文。用户提供的正文缺少网址时说明来源为用户提供，不虚构 URL；无法确认站点时，目录中的站点使用 `provided`。缺少标题时，根据内容生成简短描述性标题并注明为自拟标题。
- 不修改 `papers/` 里已有的归档文件和其他索引；`README.md` 只按「回写根 README」一节修改——默认只回写笔记地址，其余改动（追加行、新建分组、合并／改名分组、搬迁既有行）都需用户明确要求。不自动提交 Git，用户明确要求时再提交。

## 回写根 README

生成笔记后，把根 `README.md` 中对应行的「笔记地址」单元格改为笔记链接；本 skill 修改 `README.md` 仅限：回写笔记地址，以及用户明确要求时的收录与分组改动（追加行、新建分组、合并／改名分组、搬迁既有行，见本节末条）、**更换某条目编号单元格的来源指向**（如非 arXiv 来源的论文随后在 arXiv 发布、原链接失效；换链接不动其他单元格，不换编号、不删已归档的 PDF）。

- 定位唯一匹配行，按顺序尝试：先按 arXiv 编号（版本号和 `abs`、`pdf`、`html` 链接形式都视为同一篇），再按来源 URL 精确匹配，最后按与清单行完全相同的标题匹配（用于同一论文在清单中以别的来源收录，例如用 arXiv 链接读一篇清单里记成 GitHub 版的论文）。
- 同一来源存在多行（如 GitHub 版与期刊版）时，以本次实际阅读的链接那行为准；候选不唯一就按匹配不到处理，不挑一个写入。
- 单元格写成 `[笔记](./notes/<papers|blogs>/<...>/note.md)`，相对仓库根目录；该行其他单元格一律不动。
- 单元格当前是 `—（待生成笔记）` 或指向 `./notes/` 下的笔记时，写入或更新为本次的笔记链接（同一行只保留最近一次阅读的笔记）；已经指向本笔记的行不重复写入。
- 单元格里若是其他内容（用户手写的批注、外部链接等），不覆盖，保持原样并在对话中说明。
- 匹配不到、命中多行或论文不在清单中时，保持 `README.md` 原样并在对话中说明，由用户决定是否收录。
- **用户明确要求收录并分配编号时**（导读、博客、系统这类非论文条目常这样进清单），按上一节的规则取号：能归入既有同机构分组（含其子团队／子实验室）就追加到该组末尾；单位／署名方只有 1 个条目时不新建分组，追加到「### 其他」末尾；用户明确要求新建分组时按其确认的机构／署名方命名、插在「### 其他」之前，不重排既有分组。编号单元格写原文在线地址（无 PDF 可归档），论文单元格写标题并链到同一地址，单位按条目类型写第一机构／署名方原值（归并分组不改写该列），笔记地址写本次笔记链接；不改表头、不动其他行。撤并、改名分组或搬迁既有行只在用户明确要求时执行。

## 交付前检查

检查笔记中的本地链接与图片是否存在、来源和版本是否一致、核心数值是否能回溯到原文，以及阅读范围说明是否符合实际；逐条打开核对自己写的 `§x.y`、`Figure n`、`Table n` 与公式编号是否指向正确内容，未编号的公式不编造编号。回写了 `README.md` 时，一并核对这一行：编号列的链接按条目类型可达（论文指向确实存在的 PDF，非论文条目指向可达的原文在线地址）、编号未与两侧最大值撞号、笔记链接可达。缺失内容如实标注，不为填满章节而推测。

完成后在对话中给出核心结论，并说明影响理解的材料缺失或未验证事项。生成了文件时附笔记及实际归档的 PDF 路径（arXiv 论文不归档 PDF、只附 note.md 链接）；仅对话解答时直接交付解读，不输出未创建文件的链接。
