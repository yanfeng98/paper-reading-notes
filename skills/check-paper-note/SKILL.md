# 笔记复核

对已生成的笔记做一次与原文的对照复核，默认**动手修复**（用户明确只要报告时除外）。复核的基准是原文——不是记忆，也不是笔记自身。每条事实性陈述都要回到原文确认。

## 第一步：确定复核基准

1. 定位笔记：给路径直接读；给标题或 arXiv 编号时在 `notes/*/*/` 下按目录名与笔记标题匹配；**给清单编号时先查 README 该行的「笔记地址」单元格**，单元格未回写或指向不存在的文件时，在 `notes/` 下按标题搜索再判断。只说「最近生成的笔记」时按修改时间定位（如 `ls -t notes/*/*/note.md`）。**候选不唯一或无法判断时直接询问用户。** 本 skill 所在目录为 `<仓库根>/skills/check-paper-note/`，默认以该仓库根目录定位 `notes/` 与 `papers/`，不依赖调用时的工作目录；经符号链接加载时先解析真实路径。对应笔记不存在时说明情况并询问用户——笔记生成是 read-paper-blog 的职责。
2. 读笔记头部「来源信息」：来源类型、版本（arXiv 要具体到 vN）、原文链接、本地归档路径、阅读日期、阅读范围声明——这些决定拿什么版本核对（字段缺项按「本项不适用」处理）。没有来源信息表时，用目录名与 README 对应行推断编号与版本；仍无法确定就先询问用户，版本一律以记录为准。
3. **重新获取原文**（核对基准一律来自本次重新获取的原文，而非记忆或上次阅读的印象）：
   - arXiv：取笔记记录的**那个版本**；PDF 必取，官方 HTML **若存在**也取（便于文本与公式交叉核验，老论文可能没有）。下载到临时文件（`curl -sL -o /tmp/x.pdf https://arxiv.org/pdf/<id>v<N>`）。**下载后必须校验**：用 `file` 确认确实是 PDF（页数以 `pdfinfo` 为准，`file` 报的页数不可靠）且规模合理——`curl` 对不存在的版本会返回 exit 0 并静默写入 HTML 错误页；校验失败一律按「取不到原文」处理。多 MB 文件的下载可能超过单次命令超时：转后台下载或重试，以完整文件为准（`pdfinfo` 可解析）；半截文件的 xref/trailer 报错是预期现象，不代表文件损坏。
   - 非 arXiv：优先读仓库 `papers/<编号>-<短标题>.pdf`；必要时按笔记中的链接重新获取。`provided.pdf` 只作参考，不同于原文。
   - 博客：按笔记记录的锚点重新取（源文件路径 + commit + sha256）；正文在源码仓库时走 GitHub API 取源 markdown，页面可能已更新——更新过的按「文章所述版本」核对。细节见「博客笔记的差异」一节。
4. 同时准备两种材料：文本抽取用于检索（`pdftotext -layout`；注意它会折行，搜长句前先把换行替换为空格），页面渲染用于定论（`pdftoppm -r 220 -png`，分辨率按需调高，配合读图工具查看）。公式、上下标、表格一律以渲染页为准，文本抽取只当索引；**grep 未命中不等于原文没有**——先排查折行、连字（如 `Tflops` 常被拆成 `T f lops`）、空格差异与自己检索串的用词，必要时看渲染页，再下结论。命令不可用时改用环境已有的等价能力，不假定专用工具存在，也不默认安装依赖。
5. 原文取不到时：先试其他官方格式（abs 页、官方 HTML、镜像）；仍失败就只在可核验范围内核对（内部一致性、可复算的换算、公开可查的事实），交付时如实声明缺失范围。

## 逐条核对

每一项都要给出结论（符合 / 有问题 / 本笔记不适用），这是复核的完成判据。

**A. 元数据**：标题、作者、机构、日期、版本号与版本历史（撤回/新旧版差异）、链接可达性；阅读范围声明与实际核对范围是否相符。若正文数字/机制与记录的版本对不上，先取相邻版本（vN±1）确认笔记实际基于哪一版，再决定改正文还是改版本声明；相邻版本不可得时（如已撤稿不再提供）用投稿历史与元数据做旁证，并声明该步未执行。清单编号列链接的**上游归档 PDF** 也要核验：它可能是删改/学习版，与笔记所用版本不同——确认关系（常用手段：下载后与基准版做 **sha256 字节比对**，一致即「上游 = 基准版」，写进复核记录；不一致再按页数与多组关键句比对内容），必要时在笔记的来源信息中注明。链接用 `curl` 等复核可达性；被网络策略完全拦截的域名如实标注「本机无法验证，链接字符串与原文一致」，不判为错误。阅读范围声明里列举的核对手段必须在笔记中有对应产出（例如声明了像素测量就要有图中读数）；声明里记了核对凭据（渲染 DPI、裁剪框坐标、定标锚点、检索词）的，按凭据复跑一步确认可复现。**公开版本现状是本项的必查内容**：按标题查 arXiv（`export.arxiv.org/api/query?search_query=ti:"<title>"` 或直接查同名条目），再看项目页/仓库是否标注新版本——**非 arXiv 来源的笔记同样要查**（有「疑似 arXiv 编号、未核验」记录的必须核）；网络不可达则保持「未核验」并如实声明。若存在比基准更新的版本，下载比对关键数字与关键表述（**多组关键句检索**，不能只看标题/摘要），把差异写进报告。这一步不能省：实际发生过基准版（项目页 36 页）其实已有 arXiv v1/v2，其中 **v2（43 页）是实质修订版，恰好改掉了笔记列出的 5 条「原文自身的表述张力」**——不查就会把作者已修正的表述长期当成现行问题。**仓库/项目页/README 自述的状态（发布渠道、许可、star 等）属「材料声称」，不是核验结果**，要独立核验并注明核验方式与日期。**条目占了编号时另核 README 那一行**：编号单元格的链接类型要与条目类型相符（论文指向本仓库或上游的 PDF，非论文条目指向原文在线地址）、链接可达、笔记链接可达、编号未与 `papers/` 文件名或上游归档撞号。

**B. 数字**：逐一回原文——内存、性能、规模、百分比、倍数。表格类数字（实验配置表、内存表）**必须在渲染页上核对**，文本抽取经常错位丢列。笔记若把原文表格重排、摘列或改列名，按**列语义映射**逐格核对，不能按位置对照（先建立映射再核对）；除渲染页逐格外，可再用文本层做一次「**按序子序列**」机器比对（笔记该行的每个数值须按原文列序出现在对应页文本里）作为补充——两种手段互补，不能只靠文本层。**篇幅类数字**（「约 N 页」「pp.a–b」、附录跨度）同样要核：逐页检索标题定位起止页（实际发生过两处附录页数写错——约 5 页写成 15 页、约 10 页写成 14 页）。声称的换算自己复算（例：卡数 × 每卡 TFlops ≈ 总 PFlops），推算要写出算式与实测偏差，不用「约 1% 以内」这类模糊措辞。

**C. 公式**：变量、系数、上下标、单位逐项核对，看渲染页而非文本抽取；公式编号与正文引用对得上。

**D. 引用定位**：每个 `§x.y`、`Figure n`、`Table n`、脚注 n 都打开原位置确认**内容与归属**——不仅要问「该处有没有这个内容」，还要问「笔记说它出自这里，对不对」（摘要 / 引言 / 结论 / 图注的措辞常近似；实例：笔记把 §1 引言里的一整段逐域结果声明写成「摘要写」，而摘要全篇没有数字）。注意原文自身可能有错标（例：附录表格图号与内容错位；正文称某组超参「reported in Table n」而该表并无这几行）——发现时把它标注为原文自身的问题（不是笔记的错误），并以「另注（复核时发现）」等形式写进笔记、在对话说明，方便下次复核查证。HTML（LaTeXML）与 PDF 的参考文献编号可能不一致，引用编号以 PDF 渲染页为准。断言某说法在摘要/引言/结论**重复**、或说某处「未带限定词」时，把**每一处**（含 §6 开头与 §6.2 这类相邻位置）都打开核对完整句子与后半句限定——各处的措辞与限定并不相同（实际发生过：把 §6 开头段误写成「§6.2 结论重复」，而 §6.2 并无该句、§6 开头那句还自带 code/search 限定）。

**E. 声称 vs 证据**：搜出所有「论文称 / 原文 / §x」样式的句子逐字对照；超出原文的概括要么改回原文说法，要么标注「解读/推断」。区分作者明说的局限与读者视角的判断。原文自身前后有张力时（例：§1 的通信量声明与 §5.1 的机制描述不完全自洽），如实记录张力与两种读法，并标明这是原文自身的表述张力。对「论文未给出/未说明」类否定性断言，须用全文（HTML 与 PDF）多组关键词检索确认，报告中说明检索的用词；不能凭印象下结论。把所有「全部/均/全面/无一例外」类全称断言单独列出、逐项回表格与正文找反例——实战中该类断言是审计与自查的主要漏网点。对**材料自身**的否定性断言（笔记写「导读未引」「材料未注明」「§x 没有给代表工作」）同样要检索确认：搜材料的完整正文，并覆盖它的全部语言版本（双语站点常只更新一侧）；报告里写明检索用的词。

**F. 读图**：图注里的每个数值、曲线关系、图例归属都要实测（目测只用于定位，不用于定论）。双轴图最容易把系列画错轴；把「图中读数」写成论文数字也是常见错误。正文/图注里「某系列**始终**更优」「**一致**更低」这类断言要**按 x 逐段比对**，不能只看终值，并在报告里给出反例区间（实例：两条 "consistently" 断言分别在折线第 4 轮与早期区间找到反例）。方法见下节。另核笔记的**排除性声明**是否与材料相符：写了「未做像素测量」「插图均为示意图」的，抽查图像确认该声明没被某个含色标或内嵌图表的定量图打破（实际发生过「均为示意图」而其中 2 张含定量元素）。

**G. 遗漏**：影响理解的实验条件与口径（硬件、并行布置、baseline 设置、比较口径、附录里的补充声明）、作者明说的局限、论证链上的关键中间结论。不求全求细，但影响解读的必须在。

**H. 内部一致性**：同一数字/结论在全文多处表述一致、无自相矛盾；本地链接与图片存在、表格列数一致、代码块闭合、配图确实是所标注的那张（可用「从 PDF 同坐标重新裁剪并与笔记图片做像素差比对」快速确认）。**注意像素差 ≈0 只证明裁剪位置与原文一致，不证明边界选得对**——还要放大看图的四边，确认没有把图注或正文切掉一半（实际发生过：裁图与原文逐像素一致，但下边界切穿了图注首行，而笔记声明「无截断」）；另核**框内元素是否齐全**——边缘干净只说明没切到东西，不说明没有元素整块留在框外，按整页行剖面逐类点名（图内标题、图例、坐标轴标签（含位于整图底部的共享轴标签）、图内说明行、色标）（实际发生过：配图边缘干净、像素差为 0，却整行漏掉图内底部说明行）。

## 读图的像素测量

关键图表读数（双轴、多系列、对数轴）用像素测量定论：

1. 高分辨率渲染页面（`pdftoppm -r 220 -png`，像素测量读数建议 ≥300 dpi），先看图确认图例、轴与系列的大致归属。**同一批测量固定 DPI**：像素坐标只在同一渲染文件内有效，换 DPI 必须重新定标（实例：先在 220 dpi 图上套用 300 dpi 的坐标，白跑一轮）。
2. 用脚本按颜色提取数据点/柱/线（如 Python + PIL 读像素），按 x 位置求每列的 y 中心。注意：柱体填充色与网格线颜色可能不同，阈值要分别取、取准；两者区分不开时，柱顶改用**形状法**定位（自下而上的连续填充段），不用「最上方的命中像素」，否则网格线会被当成柱顶。图例（色块、样线）与**陡峭的线段**都会形成伪点——按数据点的预期 x 位置（类别中心）与形状筛选，先排除图例区，再定数据点。另两类同样常见的伪数据源：**坐标轴箭头/轴端装饰**常与数据曲线同色，会被掩码命中（实例：横轴箭头被当成数据点，把固定策略的曲线末端从 ≈998 代误读成 ≈1033 代）→ 测量前按面板/绘图区边界截断，或排除轴所在的行列；**与系列同色的文字标注**（轮次编号、数据标签、数值文字）也会进掩码（实例：红色曲线旁的轮次数字把某点读数拉高 ≈70 ms／1.3%）→ 定值用标记形状，并先排除文字所在的行。散点/圆点等标记用**连通域质心**定值，不要用最上/最下的边缘像素——标记半径会使读数系统性偏大或偏小（实例：平台值用边缘像素读出 78.8，质心为 78.4，后者与表格一致）。
3. 用刻度标签或网格线定标：找标签文字的 y 中心或网格线行，建立「像素 ↔ 数值」映射，先确认轴是线性还是对数、左右轴是否不同量纲；刻度密集、文字行检测有噪声时，改用网格线行定标或放大目读刻度。定标前先放大**核对刻度标签文字本身**再建立映射——错认刻度（实例：把 7–14 的纵轴读成 3–15；把坐标轴下限当成曲线起点）会造成整体性偏差，是本类错误的头号来源。
4. **交叉验证**：同一数据的不同呈现应互相吻合（例如总量曲线 ÷ 卡数 == 每卡柱；同一实验在另一张图里的点应一致）；不吻合就继续查，查清再下结论。
5. 写进笔记时标注「图中读数」并给不确定度（写明**取数口径**：质心/顶点/边缘），与论文数字区分。折线剧烈升降（V 形回落、陡升段）处取点，窗口内的像素簇会混入线画段——用标记形状定心（连通域质心），复核时先对齐口径再比数（实际发生过：簇心口径把一点低估约 2.5 分，按质心口径修正）。

## 独立复核

默认执行：另派一个子 agent 做独立审计（它没有你的上下文包袱，容易发现你忽略的问题；历史上它抓到过自查漏掉的问题）。只有复核范围很小（只查单点疑问、不查全篇）时才跳过。给它的材料：原文获取方式（具体命令）、笔记路径、上面的核对清单、以及「只报告、不改文件」的要求，让它按位置给出「笔记原文 / 原文依据 / 判定」清单。**对它报告的问题逐条自己验证**（尤其数字和图），确认后再改——子 agent 也会读错图、算错数。与子 agent 的读数出现小数级差异时，自己复测定夺，并说明保留哪个值及依据。派发前**固化笔记快照**（记录 md5 或 mtime 并写进提示）。**审计期间自己不要在同一个文件上落笔**——把自查发现的修改先记成待改清单，等审计报告回来一次性改；否则行号与磁盘状态错位，审计报告里的每条都要额外标注版本（实际发生过：审计期间笔记被改两次，报告需逐条标「已修正／仍存在」）。确需中途修改时，在报告中按新快照对齐行号，避免行号漂移。要求它在报告末尾给出**覆盖度小结**（A–H 哪些项逐项查过、哪些未查），便于判断盲区。子 agent 可能分批送达并**自我修正**（实际发生过先报「全部图为示意图」、补充时才更正为「其中 2 张含定量元素」，也有审计期间它自己的下载还在跑的情况）——以它最后一份报告为准，把两版差异并入你的复验，并在最终报告里说明取了哪一版。

## 修复规则

- 先改「确凿错误」，再处理「易误读」的表述；不确定的宁可不改，或在笔记中标注不确定性。
- 修完必须回原文验证新文字本身，避免补丁引入新错误。
- 自己的推断被证伪时直接删改；修复的是事实，加限定词不算修复。
- 以最小改动修复，保留笔记中的人工内容、批注与待办；无法区分归属时追加带日期的补充。
- 改动限定在该笔记目录内（`note.md` 与 `assets/`）。`papers/`、其他笔记、README 默认不动；仅当发现清单里该论文的笔记链接失效，或单元格仍未回写（`—（待生成笔记）`）而笔记已存在时，按 read-paper-blog 的「回写根 README」规则修正那一格——匹配不到、命中多行或单元格是手写内容则只报告。
- 修复后重跑笔记的结构自检：本地链接与图片存在、表格列数一致、代码块与公式块闭合；改过 `assets/` 时重新与原文比对（像素差≈0）。
- 临时文件（下载的 PDF/HTML、渲染图、脚本输出）用后清理；arXiv 论文只记官方链接，不归档 PDF。
- 若发现阅读范围声明与实际不符（如声称读了全文但内容只覆盖摘要；声称某些表格/公式「已渲染页逐格核对」而实际只读过 HTML 版），**先补做缺失的核对**——把声明里列到、实际没在渲染页看过的表格、公式、图逐项补验；确认结论无误后再把声明改到实际做过的范围，而不是一删了事。反向不一致（声明**少列**了正文实际引用过的材料）同样要修：把引用到的部分补进声明，避免「引用了却没写进声明范围」（实际发生过：声明只列某附录的前 3 步与另两步，而正文引用了该附录的 06/07 步与另一附录的第 03 步）。
- 发现比基准更新的公开版本时：① 默认**不改笔记基准**（换基准＝重读，属 read-paper-blog 的职责，需用户明确要求）；② 在笔记中新增/更新「版本关系」小节（各版页数与日期、关键数字是否一致、表述与图/表编号差异、新版有哪些内容未覆盖）；③ 给「原文自身的表述张力」逐条标注适用版本与是否已在更新版修正；④ 在对话报告中说明新版有哪些内容未覆盖、哪些张力已失效。若该论文同时是**仓库归档版**，一并核对清单那一行的编号单元格指向是否需要按用户要求调整（只报告，不自行改）。
- 复核完成后在笔记的「来源信息」中追加或更新一条「复核记录」（日期、基准版本、核对方式、修正摘要；修正摘要里一并写**未修项与理由**，如「原文未给口径、无法复算」），便于追溯与下次复核；记录里带上本次用到的**可复现凭据**（渲染 DPI、裁剪框坐标、定标锚点、否定性断言的检索词），下次复核可直接复用。

## 交付

对话中报告：

1. 核对范围与方式（原文版本、用过的核对手段、全查还是抽查）；
2. 确认无误的部分，写明对应「逐条核对」A–H 中的哪些项；
3. 问题清单：位置（行号 + 原文片段）、原文依据（页码/节/图表号）、判定（事实错误 / 未标注推断 / 遗漏 / 易误读）、修法；
4. 已修复内容（只报告未修改时写明）；仍未核实或无法核实的事项。

报告只声明实际核对过的范围。生成的文件有变化时附路径；仅对话解答时不输出文件链接。一次复核多篇时，逐篇独立执行本流程、各自使用独立的临时文件，逐篇给出上述四项报告。

## 博客笔记的差异

博客没有版本号，版本锚点是笔记记录的**源文件路径、commit 与 sha256**：重取后先比对这些锚点——一致即基准未变，可放心引用行号与原文片段；不一致再查明改动，按「文章所述版本」核对。笔记没记锚点时，退而比对笔记里的原文引用。

站点是 JS 单页应用时**不能只抓 HTML 壳**（那只是一个 `#root` 空容器，核不到任何正文）：到源码仓库取源 markdown（如 `site/src/data/blog/*.md`）再核；双语站点两个语言版本都取回，数字与机制以两版一致为准。`raw.githubusercontent.com` 不可达时用 GitHub API 的 blob 接口（`/repos/<owner>/<repo>/git/blobs/<sha>` 返回 base64）。

用户需要当前行为时查官方文档并标注来源。代码示例连同依赖与上下文一起核对。

## 转引型材料的核对

笔记的「原文」若本身是转引（导读、综述、awesome list），要核两层：**①笔记 ↔ 这份材料**（转写是否忠实）与 **②材料 ↔ 被引论文**（转引是否忠实）。第二层的核对目标只是「转引是否忠实」，不是「结论是否成立」——报告里要写清这一区分。

1. 被引论文的元信息（编号、标题、第一作者、日期）批量核：arXiv 一次可查多篇（`export.arxiv.org/api/query?id_list=a,b,c`），与材料的参考列表逐条比对；材料标的日期常是 v1 提交日期，核数字时以各自最新版为准并注明。
2. 数字逐条回摘要；只有承载结论的数字才取全文或复算表格（表格仍在渲染页核对）。**范围型数字**（如「提高 3.7–6.2 个百分点」）先判它是不是原文原话——全书检索该范围的两端；不是原话时按材料的表格复算，并在笔记里注明这是复算值及其基线选择。
3. 材料转引时的取舍也要记录：省略了哪些更强的结果、哪些限定词（子集口径、backbone、评测预算）被丢掉、哪条数字其实来自论文而非材料。
4. 笔记要标明每条数字的核对层级（元信息／摘要／全文／复算／未核），未取到全文的如实保留「未核」。

## 边界

- 复核只做静态核对（阅读、取原文、渲染、比对）；运行文章代码、训练模型、复现实验超出范围（用户明确要求时另说）。
- 离线时只做可离线核验的部分，并声明这一点。
- 复核只解决两类问题：「与原文不符」与「影响理解的遗漏」；润色、扩写、换结构不属于复核范围。
