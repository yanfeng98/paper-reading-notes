# 笔记复核

对已生成的笔记做一次与原文的对照复核，默认**动手修复**（用户明确只要报告时除外）。复核的基准是原文——不是记忆，也不是笔记自身。每条事实性陈述都要回到原文确认。

## 第一步：确定复核基准

1. 定位笔记：给路径直接读；给标题或 arXiv 编号时在 `notes/*/*/` 下按目录名与笔记标题匹配；**给清单编号时先查 README 该行的「笔记地址」单元格**，单元格未回写或指向不存在的文件时，在 `notes/` 下按标题搜索再判断。只说「最近生成的笔记」时按修改时间定位（如 `ls -t notes/*/*/note.md`）。**候选不唯一或无法判断时直接询问用户。** 本 skill 所在目录为 `<仓库根>/skills/check-paper-note/`，默认以该仓库根目录定位 `notes/` 与 `papers/`，不依赖调用时的工作目录；经符号链接加载时先解析真实路径。对应笔记不存在时说明情况并询问用户——笔记生成是 read-paper-blog 的职责。
2. 读笔记头部「来源信息」：来源类型、版本（arXiv 要具体到 vN）、原文链接、本地归档路径、阅读日期、阅读范围声明——这些决定拿什么版本核对（字段缺项按「本项不适用」处理）。没有来源信息表时，用目录名与 README 对应行推断编号与版本；仍无法确定就先询问用户，版本一律以记录为准。
3. **重新获取原文**（核对基准一律来自本次重新获取的原文，而非记忆或上次阅读的印象）：
   - arXiv：取笔记记录的**那个版本**；PDF 必取，官方 HTML **若存在**也取（便于文本与公式交叉核验，老论文可能没有）。下载到临时文件（`curl -sL -o /tmp/x.pdf https://arxiv.org/pdf/<id>v<N>`）。**下载后必须校验**：用 `file` 确认确实是 PDF（页数以 `pdfinfo` 为准，`file` 报的页数不可靠）且规模合理——`curl` 对不存在的版本会返回 exit 0 并静默写入 HTML 错误页；校验失败一律按「取不到原文」处理。多 MB 文件的下载可能超过单次命令超时：转后台下载或重试，以完整文件为准（`pdfinfo` 可解析）；半截文件的 xref/trailer 报错是预期现象，不代表文件损坏。
   - 非 arXiv：优先读仓库 `papers/<编号>-<短标题>.pdf`；必要时按笔记中的链接重新获取。`provided.pdf` 只作参考，不同于原文。
   - 博客：重新抓取该 URL。页面可能已更新——更新过的页面按「文章所述版本」核对；需要当前行为时另查官方文档并标注来源。
4. 同时准备两种材料：文本抽取用于检索（`pdftotext -layout`；注意它会折行，搜长句前先把换行替换为空格），页面渲染用于定论（`pdftoppm -r 220 -png`，分辨率按需调高，配合读图工具查看）。公式、上下标、表格一律以渲染页为准，文本抽取只当索引；**grep 未命中不等于原文没有**——先排查折行、连字（如 `Tflops` 常被拆成 `T f lops`）、空格差异与自己检索串的用词，必要时看渲染页，再下结论。命令不可用时改用环境已有的等价能力，不假定专用工具存在，也不默认安装依赖。
5. 原文取不到时：先试其他官方格式（abs 页、官方 HTML、镜像）；仍失败就只在可核验范围内核对（内部一致性、可复算的换算、公开可查的事实），交付时如实声明缺失范围。

## 逐条核对

每一项都要给出结论（符合 / 有问题 / 本笔记不适用），这是复核的完成判据。

**A. 元数据**：标题、作者、机构、日期、版本号与版本历史（撤回/新旧版差异）、链接可达性；阅读范围声明与实际核对范围是否相符。若正文数字/机制与记录的版本对不上，先取相邻版本（vN±1）确认笔记实际基于哪一版，再决定改正文还是改版本声明；相邻版本不可得时（如已撤稿不再提供）用投稿历史与元数据做旁证，并声明该步未执行。清单编号列链接的**上游归档 PDF** 也要核验：它可能是删改/学习版，与笔记所用版本不同——确认关系，必要时在笔记的来源信息中注明。链接用 `curl` 等复核可达性；被网络策略完全拦截的域名如实标注「本机无法验证，链接字符串与原文一致」，不判为错误。阅读范围声明里列举的核对手段必须在笔记中有对应产出（例如声明了像素测量就要有图中读数）；非 arXiv 笔记若记录了「疑似 arXiv 版本、未核验」，复核时网络可达则尝试核验，不可达则保持「未核验」并如实声明。

**B. 数字**：逐一回原文——内存、性能、规模、百分比、倍数。表格类数字（实验配置表、内存表）**必须在渲染页上核对**，文本抽取经常错位丢列。笔记若把原文表格重排、摘列或改列名，按**列语义映射**逐格核对，不能按位置对照（先建立映射再核对）。声称的换算自己复算（例：卡数 × 每卡 TFlops ≈ 总 PFlops），推算要写出算式与实测偏差，不用「约 1% 以内」这类模糊措辞。

**C. 公式**：变量、系数、上下标、单位逐项核对，看渲染页而非文本抽取；公式编号与正文引用对得上。

**D. 引用定位**：每个 `§x.y`、`Figure n`、`Table n`、脚注 n 都打开原位置确认内容。注意原文自身可能有错标（例：附录表格图号与内容错位）——发现时把它标注为原文自身的问题（不是笔记的错误），并以「另注（复核时发现）」等形式写进笔记、在对话说明，方便下次复核查证。HTML（LaTeXML）与 PDF 的参考文献编号可能不一致，引用编号以 PDF 渲染页为准。

**E. 声称 vs 证据**：搜出所有「论文称 / 原文 / §x」样式的句子逐字对照；超出原文的概括要么改回原文说法，要么标注「解读/推断」。区分作者明说的局限与读者视角的判断。原文自身前后有张力时（例：§1 的通信量声明与 §5.1 的机制描述不完全自洽），如实记录张力与两种读法，并标明这是原文自身的表述张力。对「论文未给出/未说明」类否定性断言，须用全文（HTML 与 PDF）多组关键词检索确认，报告中说明检索的用词；不能凭印象下结论。把所有「全部/均/全面/无一例外」类全称断言单独列出、逐项回表格与正文找反例——实战中该类断言是审计与自查的主要漏网点。

**F. 读图**：图注里的每个数值、曲线关系、图例归属都要实测（目测只用于定位，不用于定论）。双轴图最容易把系列画错轴；把「图中读数」写成论文数字也是常见错误。方法见下节。

**G. 遗漏**：影响理解的实验条件与口径（硬件、并行布置、baseline 设置、比较口径、附录里的补充声明）、作者明说的局限、论证链上的关键中间结论。不求全求细，但影响解读的必须在。

**H. 内部一致性**：同一数字/结论在全文多处表述一致、无自相矛盾；本地链接与图片存在、表格列数一致、代码块闭合、配图确实是所标注的那张（可用「从 PDF 同坐标重新裁剪并与笔记图片做像素差比对」快速确认）。

## 读图的像素测量

关键图表读数（双轴、多系列、对数轴）用像素测量定论：

1. 高分辨率渲染页面（`pdftoppm -r 220 -png`，像素测量读数建议 ≥300 dpi），先看图确认图例、轴与系列的大致归属。
2. 用脚本按颜色提取数据点/柱/线（如 Python + PIL 读像素），按 x 位置求每列的 y 中心。注意：柱体填充色与网格线颜色可能不同，阈值要分别取、取准；两者区分不开时，柱顶改用**形状法**定位（自下而上的连续填充段），不用「最上方的命中像素」，否则网格线会被当成柱顶。图例（色块、样线）与**陡峭的线段**都会形成伪点——按数据点的预期 x 位置（类别中心）与形状筛选，先排除图例区，再定数据点。散点/圆点等标记用**连通域质心**定值，不要用最上/最下的边缘像素——标记半径会使读数系统性偏大或偏小（实例：平台值用边缘像素读出 78.8，质心为 78.4，后者与表格一致）。
3. 用刻度标签或网格线定标：找标签文字的 y 中心或网格线行，建立「像素 ↔ 数值」映射，先确认轴是线性还是对数、左右轴是否不同量纲；刻度密集、文字行检测有噪声时，改用网格线行定标或放大目读刻度。定标前先放大**核对刻度标签文字本身**再建立映射——错认刻度（实例：把 7–14 的纵轴读成 3–15；把坐标轴下限当成曲线起点）会造成整体性偏差，是本类错误的头号来源。
4. **交叉验证**：同一数据的不同呈现应互相吻合（例如总量曲线 ÷ 卡数 == 每卡柱；同一实验在另一张图里的点应一致）；不吻合就继续查，查清再下结论。
5. 写进笔记时标注「图中读数」并给不确定度，与论文数字区分。

## 独立复核

默认执行：另派一个子 agent 做独立审计（它没有你的上下文包袱，容易发现你忽略的问题；历史上它抓到过自查漏掉的问题）。只有复核范围很小（只查单点疑问、不查全篇）时才跳过。给它的材料：原文获取方式（具体命令）、笔记路径、上面的核对清单、以及「只报告、不改文件」的要求，让它按位置给出「笔记原文 / 原文依据 / 判定」清单。**对它报告的问题逐条自己验证**（尤其数字和图），确认后再改——子 agent 也会读错图、算错数。与子 agent 的读数出现小数级差异时，自己复测定夺，并说明保留哪个值及依据。派发前**固化笔记快照**（记录 md5 或 mtime 并写进提示），审计期间不要改笔记；确需修改时在报告中按新快照对齐行号，避免行号漂移。要求它在报告末尾给出**覆盖度小结**（A–H 哪些项逐项查过、哪些未查），便于判断盲区。

## 修复规则

- 先改「确凿错误」，再处理「易误读」的表述；不确定的宁可不改，或在笔记中标注不确定性。
- 修完必须回原文验证新文字本身，避免补丁引入新错误。
- 自己的推断被证伪时直接删改；修复的是事实，加限定词不算修复。
- 以最小改动修复，保留笔记中的人工内容、批注与待办；无法区分归属时追加带日期的补充。
- 改动限定在该笔记目录内（`note.md` 与 `assets/`）。`papers/`、其他笔记、README 默认不动；仅当发现清单里该论文的笔记链接失效，或单元格仍未回写（`—（待生成笔记）`）而笔记已存在时，按 read-paper-blog 的「回写根 README」规则修正那一格——匹配不到、命中多行或单元格是手写内容则只报告。
- 修复后重跑笔记的结构自检：本地链接与图片存在、表格列数一致、代码块与公式块闭合；改过 `assets/` 时重新与原文比对（像素差≈0）。
- 临时文件（下载的 PDF/HTML、渲染图、脚本输出）用后清理；arXiv 论文只记官方链接，不归档 PDF。
- 若发现阅读范围声明与实际不符（如声称读了全文但内容显示只覆盖摘要），修正声明。
- 复核完成后在笔记的「来源信息」中追加或更新一条「复核记录」（日期、基准版本、核对方式、修正摘要），便于追溯与下次复核。

## 交付

对话中报告：

1. 核对范围与方式（原文版本、用过的核对手段、全查还是抽查）；
2. 确认无误的部分，写明对应「逐条核对」A–H 中的哪些项；
3. 问题清单：位置（行号 + 原文片段）、原文依据（页码/节/图表号）、判定（事实错误 / 未标注推断 / 遗漏 / 易误读）、修法；
4. 已修复内容（只报告未修改时写明）；仍未核实或无法核实的事项。

报告只声明实际核对过的范围。生成的文件有变化时附路径；仅对话解答时不输出文件链接。一次复核多篇时，逐篇独立执行本流程、各自使用独立的临时文件，逐篇给出上述四项报告。

## 博客笔记的差异

博客没有版本号，但同一 URL 内容可能更新：重新抓取后先与笔记引用比对，不一致时查明改动，按「文章所述版本」核对；用户需要当前行为时查官方文档并标注来源。代码示例连同依赖与上下文一起核对。

## 边界

- 复核只做静态核对（阅读、取原文、渲染、比对）；运行文章代码、训练模型、复现实验超出范围（用户明确要求时另说）。
- 离线时只做可离线核验的部分，并声明这一点。
- 复核只解决两类问题：「与原文不符」与「影响理解的遗漏」；润色、扩写、换结构不属于复核范围。
