## 工程实现与外部资料

### 3.1 Kernel 融合

mHC 的系数计算涉及 $\tilde{x} \in R^{1\times nC}$、$\phi \in R^{nC\times (n^2+2n)}$，以及 RMSNorm、Sigmoid、Sinkhorn 等一串小操作。原文用三个专用 kernel 计算 `H_pre/H_post/H_res`，再用两个 kernel 应用映射：

- 把 $\phi$、bias、RMSNorm 权重合并；$\phi$ 用 tfloat32，`x̃` 用 bfloat16，$\alpha/b$ 用 float32；
- 先算 $\tilde{x}\phi$，再除以 $r=\|\tilde{x}\|_2/\sqrt{nC}$，把 RMSNorm 的除法移到矩阵乘之后，数学等价但减少高维归一化的延迟；
- Sinkhorn 的 20 次迭代放在一个 kernel 内，反向用自定义 kernel 在片上重算中间结果，避免存 20 步的中间矩阵；
- 应用 kernel 把 $H_{\mathrm{post}}$ 与 $H_{\mathrm{res}}$ 的写回和残差合并融合，读从 `(3n+1)C` 降到 `(n+1)C`，写从 `3nC` 降到 $nC$。

### 3.2 选择性重算

n 流残差的主要显存开销不是权重，而是每层的 $x_{l}$、$H_{\mathrm{pre}} x_{l}$、$\mathrm{RMSNorm}(H_{\mathrm{pre}} x_{l})$ 等激活。mHC 在前向之后丢弃这些中间激活，反向时只重跑 mHC 的轻量 kernel，不重跑计算密集的 $F$。对于连续 $L_{r}$ 层，只需持久保存第一层的输入 $x_{l0}$；块内的瞬态激活约为 $(n+2)C\cdot L_{r}$（Table 3）。最优块长由「持久保存的块首输入」与「块内瞬态激活」的权衡给出：

```math
L_r^*=\arg\min_{L_r}\left[nC\left\lceil\frac{L}{L_r}\right\rceil+(n+2)C\,L_r\right]
\approx\sqrt{\frac{nL}{n+2}}
```

原文观察到理论最优值通常与每个流水线 stage 的层数接近，因此直接把重算块边界对齐到 pipeline stage 边界。这样既减少显存，又不让重算跨越 stage 造成额外通信。

### 3.3 DualPipe 重叠

n 流残差在 pipeline stage 边界处会增加通信量，重算也会在边界处引入计算尖峰。原文扩展了 DualPipe 调度（图 4；图中块长仅示意，不代表实际时长）：

- 把 MLP 的 `F_post,res` kernel 放到独立的高优先级计算流，避免阻塞通信流；
- 不对 attention 的长耗时算子使用 persistent kernel，使重叠的 attention 计算可以被抢占，减少长 stall；
- 重算与 pipeline 通信解耦，因为每个 stage 的首个激活 $x_{l0}$ 已经本地缓存。

### 3.4 6.7% 的口径

原文两处都写 6.7%：引言说「in-house large-scale training ... introduces only a 6.7% additional time overhead when n=4」，原文 §4.3 说「marginal training overhead of only 6.7%」。但原文**没有说明这 6.7% 是相对标准残差 baseline 还是相对 HC**，也没有给出 forward/backward、通信/计算的拆分。按上下文更像「相对 baseline 的端到端训练时间」，但这是推断，引用时应保留「原文未说明基准」这一限定。

### 5.1 适用场景

- 已经在用 HC 或类似的 multi-stream residual，且遇到深层训练不稳定（loss spike、grad norm 尖峰）——mHC 是最直接的替换。
- 想把残差流宽度作为一条独立于 FLOPs 的 scaling 轴，但不想承担无约束 HC 的稳定性风险。
- 有较强的 kernel/并行工程能力：从 Table 2 的 I/O 量级看，若不融合，n 流残差的读写会显著放大；因此融合、重算与 DualPipe 重叠是 6.7% 成立的前提（笔记推断），不是可选的工程细节。

### 5.2 实现顺序

1. **先做数学等价的最小实现**：flatten 输入、算三个系数、Sigmoid/2Sigmoid/20 步 Sinkhorn、按原文式 (3) 更新。先用小模型确认 loss/grad norm 正常。
2. **再做 kernel 融合**：把系数计算、Sigmoid、Sinkhorn 分别融成 kernel；Sinkhorn 的反向在片上重算，避免存 20 步中间矩阵。
3. **再做重算**：按 $L_r^{*}\approx\sqrt{nL/(n+2)}$ 选块长，并对齐 pipeline stage 边界。
4. **最后做通信重叠**：把 MLP 的 `F_post,res` 放到高优先级流；不要在 attention 里用不可抢占的 persistent kernel。
5. **测量口径**：分别报告 forward/backward、通信/计算、以及相对 baseline 与相对 HC 的开销；本文只给了 6.7% 一个总数。

### 5.3 推理侧

原文只报告训练时间开销，没有报告推理吞吐/显存。n 流残差会把激活宽度从 $C$ 增到 $nC$（27B、C=2560、n=4 时为 10240），推理时即使 batch 较小，激活显存与带宽也会增加；$H_{\mathrm{res}}$ 还会在每层增加一个 $n\times n$ 小矩阵乘。部署前应单独测 decode 阶段，不能把 6.7% 的训练开销直接当成推理开销。

### 4.3 Scaling：优势随规模的变化

图 6 有两组 scaling 曲线：compute scaling（3B/9B/27B）与 token scaling（固定 3B，1T token），每组含绝对 gap 与相对 ratio 两个 panel。按轴刻度与 marker 坐标读数（本笔记复算）：

| 曲线 | 绝对 loss gap | 相对 loss ratio |
| --- | --- | --- |
| compute：3B → 9B → 27B | 约 −0.029 → −0.023 → −0.021 | 约 98.5% → 98.7% → 98.7% |
| token：3B 早期 → 后期 | 约 −0.024 → −0.015~−0.016 | 约 98.7% → 99.1% |

- 绝对 gap 随 compute 从 −0.029 收窄到 −0.021（约缩小 28%），随 token 从 −0.024 收窄到约 −0.015~−0.016（约缩小 33%–37%）；也就是说，**绝对优势不是恒定的，规模越大/token 越多，绝对 gap 越小**。

- mHC 相对 baseline 的最终 loss reduction 为 0.021（原文 §5.2）；图 5(a) 在约 50k 处 mHC 约 −0.021、HC 约 −0.016，baseline 为 0。
- 图 5(b) 中 mHC 的梯度范数从约 0.20 平滑降到约 0.05，除个别小尖峰外贴近 baseline；HC 在约 13k 有约 0.15 的尖峰，最大尖峰在 26–30k（约 0.18），另有约 38k、49k 的次尖峰（约 0.14–0.15）。
- **图 5 与图 2 不要混读**：图 2 是 HC 相对 mHC 的对比：约 5k–9k HC 的 gap 短暂为负（6.6k 附近最低，图轴下限 −0.002 被裁切），约 10k 转正，15k 约 +0.004、18k 约 +0.006；原文 §3.1 说 12k 附近的 loss surge 与梯度不稳相关，但图 5(b) 的 12–13k 尖峰约 0.15，最大尖峰在 26–30k（约 0.18）；12k 的 loss surge 在图 2(a)，不要混读。

图 7 是传播稳定性（(a) 单层 $P_{\mathrm{Mres}}(H_{\mathrm{res}})$ 的前向信号增益与反向梯度增益；(b) 复合映射 $\prod P_{\mathrm{Mres}}(H_{\mathrm{res}})$ 的增益；灰线为前向信号增益（≈1.0），蓝线为反向梯度增益）：

- 单层映射：前向信号增益（灰线）≈1.0；反向梯度增益（蓝线）在约 1.006–1.06 之间轻微波动，来自 Sinkhorn 20 次迭代的近似误差。
- 复合映射：前向信号增益仍 ≈1.0；反向梯度增益在中间层升到约 1.6–1.65（原文写 approximately 1.6；本笔记按轴刻度读到峰值约 1.65），随后在末端回落到 ≈1.0。
- 与 HC 的约 3000（图 3(b)）相比，mHC 的复合反向增益低了约三个数量级。这里的 1.65 不是「双随机矩阵的非交换/非正规性」造成的：精确双随机矩阵对乘法封闭，行/列和都精确为 1；偏差来自 Sinkhorn 只跑 20 步，且原文式 (9) 以行归一化结束——行和精确为 1，列和只是近似为 1。从图 8 的读数看，误差在复合中放大，但**并非随深度单调累积**：第 31–60 层的 30 层复合列和可到 0.41–1.50，而全 60 层复合回到 0.88–1.11；图 7(b) 也是先升到 1.65 再回落到 ≈1.0。（行/列不对称与深度非单调都是笔记从图 7/8 读数推出的，原文只归因于迭代次数限制。）

图 8 的矩阵可视化要按层/段看，不能把单层 HC 一概说成 ±20：$H_{\mathrm{res}}^{1}$ 与 $H_{\mathrm{res}}^{60}$ 的矩阵元素约 ±5–7、行和可达约 ±22（列和约 −12..−7），但 $H_{\mathrm{res}}^{30}$ 接近单位阵（元素约 −0.14..0.94，行/列和约 0.5–1.0）。复合 HC 也不是一律放大：前 30 层复合的行/列和约 −1.4..6.5 / 1.0..1.2，后 30 层与全 60 层复合才出现 −489/+509 量级。mHC 单层行/列和约 0.96–1.04；复合行和约 1.00，后 30 层列和 0.41–1.50、全 60 层 0.88–1.11（Sinkhorn 近似误差在复合中放大，但不随深度单调），非对角项承担流间混合。图 8 的每个矩阵是选定序列上所有 token 的平均；左侧行和是前向信号增益，底部列和是反向梯度增益。原文用这张图说明「HC 在最大增益很大时，其他路径也不稳定；mHC 则整体稳定」。

### 4.5 消融的边界

Table 1 只回答了「HC 的三个映射哪个重要」，答案是 $H_{\mathrm{res}}$。它没有回答：

- $n$ 取 2/4/8 的取舍；
- Sinkhorn $t_{\max}$ 取 10/20/50 的精度-成本权衡；
- $\alpha$ 初始化、`H_pre/H_post` 非负约束的必要性；
- 去掉 tanh、改为 flatten 输入这两个参数化变化的贡献；
- 双随机约束与其他约束（正交、谱归一化、残差缩放）的对比。

这些空白使得「mHC 的哪个设计真正带来增益」无法从本文的实验里分解。原文的结论主要是「HC 的 H_res 重要 + 双随机约束能让 27B 稳定训练」，而不是「双随机是唯一/最优的约束」。

### 4.6 Table 1：HC 的组件消融

原文在 HC 上做了一个组件消融（Table 1）：按 $H_{\mathrm{res}}$ → $+H_{\mathrm{pre}}$ → $+H_{\mathrm{post}}$ 逐项启用；被禁用的映射用固定映射保持维度一致（$H_{\mathrm{pre}}$ 用 1/n 均匀权重，$H_{\mathrm{post}}$ 用全 1，$H_{\mathrm{res}}$ 用单位阵）。结果（绝对 loss gap，越负越好）：

| $H_{\mathrm{res}}$ | $H_{\mathrm{pre}}$ | $H_{\mathrm{post}}$ | Absolute Loss Gap |
| --- | --- | --- | --- |
| — | — | — | 0.0 |
| ✓ | — | — | −0.022 |
| ✓ | ✓ | — | −0.025 |
| ✓ | ✓ | ✓ | −0.027 |

按表值做算术分解，$H_{\mathrm{res}}$ 单独一行就占 full gap 的 0.022 / 0.027 ≈ 81%，$H_{\mathrm{pre}}$ 与 $H_{\mathrm{post}}$ 各只再贡献 0.003 与 0.002；这是累积消融的差值，不是因果分解。原文据此判断：**$H_{\mathrm{res}}$ 是性能增益最大的组件，说明残差流内部的信息交换很关键**；原文同时说，$H_{\mathrm{res}}$ 的顺序应用构成显著的数值稳定性风险。把这两点合称「最有效也最危险」是笔记的概括。这也符合 mHC 的设计选择：对 $H_{\mathrm{res}}$ 做强约束，而对 $H_{\mathrm{pre}}$/$H_{\mathrm{post}}$ 只加非负约束（因果方向是笔记推断，原文没有做「只约束 H_res」的对照实验）。

## 局限与待确认（完整版）

- **规模**：主实验最大 27B；原文提到「in-house large-scale training」支持 scale，但没有给出该运行的模型规模、token 数、吞吐或稳定性指标。因此「supports training at scale」的公开证据只到 27B。
- **硬件/并行规模**：论文没有给出 GPU 型号、卡数或集群规模；6.7% 与 scaling 结果的硬件环境不可复现。
- **统计**：没有随机种子、误差棒或重复次数；Table 4 中 0.4–0.6 个百分点的差距是否显著未知。Table 1 也没有说明模型规模与训练 token 数，只能支撑「H_res 最重要」的定性结论。
- **消融**：没有 mHC 自身的超参消融（n、t_max、α、非负约束、去 tanh、flatten 输入），也没有与其他流形约束的对比。
- **Sinkhorn 近似**：固定 20 次迭代，没有给出迭代收敛误差曲线或 $t_{\max}$ 消融；只给了 $t_\max=20$ 时的偏差示例/峰值（图 7 的复合反向增益约 1.65；图 8 第 31–60 层复合列和 0.41–1.50，全 60 层 0.88–1.11；图 8 是 representative mappings，不保证是最大偏差）。
- **理论边界**：只给了 $H_{\mathrm{res}}$ 的谱范数与复合封闭性，没有给整个 block（含 `H_pre/H_post/F`）的增益上界；$H_{\mathrm{post}}$ 最大为 2，层分支仍可能放大。
- **过度混合/秩坍缩**：原文认为双随机矩阵重复相乘会趋于增强流间混合（tends to），并把它描述为「robust feature fusion」；但没有分析深层（例如 60 层以上）是否会出现流间表示同质化、或置换矩阵导致的周期性。这是一个开放问题，不是原文已证实的缺陷。
- **推理成本**：未测。
- **6.7% 的基准**：未说明是相对 baseline 还是 HC，也未拆分。
- **代码/复现**：论文全文未给出代码仓库或复现说明（PDF 正文检索 `github`/`code`/`release` 均无命中；HTML 中的 `github` 命中来自 arXiv 页面模板）；本笔记未复现实验。

## 一句话取舍 / 一页速查

如果你已经在用 HC 或准备把残差流加宽，**优先抄 mHC 的 $H_{\mathrm{res}}$ 双随机投影（Sinkhorn 20 步）与 `H_pre/H_post` 非负约束**；如果只是普通残差模型、没有多流残差，mHC 的收益不适用，反而会引入 $O(n)$ 的 I/O 与 Sinkhorn 的工程复杂度。mHC 的价值不在「一个新模块」，而在「把 macro-design 的稳定性问题变成一个有明确几何约束、可 kernel 化的问题」。

| 项 | 数值 |
| --- | --- |
| 残差流扩展率 $n$ | 4 |
| Sinkhorn 迭代 $t_{\max}$ | 20 |
| 门控初始化 $\alpha$ | 0.01 |
| 额外训练时间 | 6.7%（n=4；原文未说明基准） |
| 27B 模型 | 27.0B total / 4.14B active，30 层，72 routed / 6 active / 2 shared |
| 27B 训练 | 262B tokens，batch 1280，50k steps，lr 4.0e−4，AdamW |
| 下游基准 | 8 个；mHC 对 baseline 8/8，对 HC 7/8（MATH 26.0 vs 26.4） |
| 对 HC 的增益 | BBH +2.1 pp，DROP +2.3 pp |
| 复合反向增益 | HC 约 3000 → mHC 约 1.6（本笔记读数约 1.65）；前向保持 ≈1.0 |
| 每 token 残差流 I/O（前向，不含 F 内部；n=4） | HC 读 21C+24、写 13C+24；标准残差读 2C、写 C |
| 重算块长 | $L_r^{*}\approx\sqrt{nL/(n+2)}$ |
